## 用户流程与范围

管理员为 Key 选择 Qoder 账号并填写分配额度，保存后列表、弹窗和 POST /api/usage、GET /user/balance 采用同一口径。弹窗编辑时预览新分配额度，取消不保存。账号仍独立显示上游套餐和资源包的剩余额度。

## 已确认业务规则与验收

| 场景 | 已用 | 当前分配总额 | 剩余 | 结果 |
| --- | ---: | ---: | ---: | --- |
| Key 初始分配 3000 | 0 | 3000 | 3000 | 显示 0/3000 |
| 消耗 1200 | 1200 | 3000 | 1800 | 显示 1200/3000 |
| 改为 2000 | 1200 | 2000 | 800 | 保存成功且不清零 |
| 改为 1000 | 1200 | 3000 | 1800 | 保存失败，原配置不变 |
| 改为 1200 | 1200 | 1200 | 0 | 允许，额度耗尽 |
| 改为 4000 后又消耗 500 | 1700 | 4000 | 2300 | 继续累计 |
| 账号充值但未改 Key 分配 | 1700 | 4000 | 2300 | Key 总额不自动扩大 |
| 账号充值后改为 6000 | 1700 | 6000 | 4300 | 在可分配空间内允许 |
| 共享账号 KEY_A 3000、KEY_B 2000 | A:1200 B:700 | A:3000 B:2000 | A:1800 B:1300 | 互不计入对方消耗 |

新的分配额不能小于当前已用量。多个已选账号分别保留本 Key 的消耗并汇总；消费优先级只选择下一账号，不得截断用量汇总。历史记录和重置入口保留；正常额度编辑、优先级调整、账号充值不能重置用量。

共享额度校验只预留其它 Key 尚未消费的份额；修改 Key 总额时包含它已经消费的部分，不能因已用量重复扣减而错误拒绝合法配置。

## 数据语义、异常与兼容

- 新请求 credits 来自 Qoder 真正返回的扣费，用 Key 身份和 connectionId 归属。
- 精确 ledger 优先；上游余额读取失败、增加、其它 Key 消费均不得增加本 Key 已用量。既有历史累计记录保留，不自动猜测或改写生产旧账。
- 账号上游读取失败时标明不可用，不能把未知余额当成 0 扣费。持久化 Key 用量仍可展示。
- 配置保存应保留保存瞬间最新累计扣费；校验后到落库前发生的并发扣费不能被旧快照覆盖。
- 单次模型响应可能略超分配额度：显示真实 used，不裁剪账目，remaining 下限为 0，禁止继续超预算路由。
- 移除账号沿用现有保存/取消行为，保存历史 ledger 以备重新选择；本轮不变更移除与重置产品规则。
- 两个 CC-SWITCH 接口保留字段名称，used 表示已用，balance/remaining 表示剩余，total 表示当前分配。

## 风险与非目标

账号额度与 Key 历史账并非天然等价，不能再根据账号总体下降归因到 Key。缺少 credits 的历史调用无法凭账号余额可靠恢复；本轮保留旧账并报告风险。旧版数据修复、生产部署、客户端配置修改不属于本轮授权。
