## 问题、方案与目标

管理员看到无效压缩设置、无法按 Key 追踪详情、账号额度必须整体等待、取消分配需返回上方查找账号。本次清理过时设置、增加历史名称和身份筛选、让账号查询结果真实逐条到达，并提供保存前可撤销的快捷移除。不得改变压缩策略或消费计量含义。

## 非目标

不改变压缩、重试参数含义、额度计量或其他 Key 分配；不增加 Key 重命名管理功能；不删除真实账号；不回填无法准确判断的旧数据；不运行付费生产测试，不推送或部署。

## 用户流程与前端

- 设置页原模块改为“请求重试与恢复”，只保留自动续写次数和首 Token 超时回退；复用原保存接口、默认值与合法范围。中文采用现有翻译体系。
- 使用详情在现有提供商筛选旁增加同风格原生下拉，默认全部；字段值为稳定 ID。更改任意筛选重置第一页；清除过滤同时清除 Key 条件。
- 表格新增“API Key 名称”，不破坏输出 Token 与 Credits 的相邻位置；详情抽屉同步展示名称。未知历史和明确无 Key 调用分开显示。
- 候选项来自保留详情中的 Key 身份；同一 Key 使用最近保存的历史名称作为下拉标签，不影响每行历史名称。同名附短 ID；短 ID 冲突可加长，不使用密钥前缀。删除 Key 后不丢候选身份。
- 账号弹窗先显示全部可列出的身份、原选择和顺序，每行独立 loading/ok/unavailable/missing；异步结果原位更新，不重排或覆盖用户输入。
- 必要基础分配信息和全部当前所选账号就绪后才允许保存开启限制的策略。关闭限制不依赖余额加载。全部移空时显示校验，不保存。
- 在上下箭头旁用现有图标库的 X/close 按钮，title/aria-label 标记“移除分配”；不额外弹确认框，保存与取消作为确认边界。
- 弹窗关闭、切换 Key 或重开时取消旧读取；即使取消晚到，旧响应也不能污染当前表单。

## 后端与 API 合同

### 请求身份

- 在请求处理入口取得可信 Key 身份快照，贯穿已有成功、流式失败、非流式失败和请求详情生成链路，不信任客户端任意提供的名称或 ID。
- 新详情增加 `apiKeyId: string|null`、`apiKeyName: string|null`。字段缺失代表历史未知；明确 `apiKeyId: null` 且名称为 null 代表未使用 Key。不能将无法解析的身份伪装成明确无 Key。
- `GET /api/usage/request-details` 增加可选 `apiKeyId`，与现有条件 AND 组合。分页前过滤；空条件等同不筛选，使用参数化查询。
- 同一响应附加 `apiKeys: [{id, name}]`，列出保留记录的去重身份及最近历史名称，独立于当前页面与筛选，避免删除/改名后选项消失。保留原 details/pagination 字段。
- 姓名和 ID 不携带密钥明文；存储复用详情 JSON，避免无必要的全表回填和破坏性迁移。可对 JSON 内身份参数化过滤，不根据 usageHistory 的时间匹配推测旧记录。

### 账号流

- 保留 `GET /api/keys/quota-options?excludeKeyId=...` 的原 JSON 行为，因为端点页及用量重置仍依赖它。
- 同一接口增加显式流模式，例如 `stream=1`，使用 fetch 可逐块读取的 SSE。不能以完整 JSON 返回后前端定时展示假装流式。
- 首帧 `snapshot` 提供身份列表、原有分配和本地可得数据；余额尚未查询的行带 loading 状态及 null 余额。
- 后续 `account` 帧提供单账号更新，`complete` 标记全部结束；连接级异常 `error` 可见，单账号异常记录到该行并继续其他账号。
- frame data 是 JSON；事件含 `type` 以便解析，数据不含凭证。解析兼容跨块 UTF-8 和帧边界，不能假设每次网络 read 恰好一帧。
- 固定有界并发查询，建议 3；单账号有有限超时，优先查询已选择账号。缓慢或失败账号不应阻塞快速账号发出结果。
- 响应声明 SSE、no-cache/no-transform，禁用可配置的代理缓冲提示；断连停止派发新查询，不写已关闭流。

### 保存

- `PUT /api/keys/[id]` 开启 Qoder 限制时，先校验至少一个选中 ID，再校验必要的所选账号额度与其他 Key 分配，不能仍调用查询所有账号的慢路径。
- 空选择、未知或不可用的所选账号、额度超限返回可解释的 400，原策略不变；不存在 Key 保持 404。
- 保留账号的 baseline/ledger 沿用现有保留逻辑，X 不调用重置 API；关闭限制保留原行为。
- 仅修改 Key 活跃状态、不携带 policy 时，不重解释旧空列表策略。

## 数据、权限与兼容

- 详情使用追加字段，不改变既有 ID、保留上限和 usage 统计；旧记录读取时显示未知，禁止全库推测回填。
- 候选项和增量接口复用现有管理员鉴权；不得为新路径绕过鉴权。
- 策略保存继续服务端权威校验；未知余额与 0 分开处理。
- 旧 JSON 消费者合同保持，新增模式独立启用；回滚前端和服务代码可忽略新增 JSON 字段。

## 性能与错误边界

- 身份在请求生命周期内只解析一次，不在每个流 chunk 查数据库。
- 详情候选限定现有保留记录，不引入无界请求正文扫描或逐行密钥查找。
- 余额查询限制并发和超时；取消读取时释放消费者。已选账号失效仍保留可移除占位行。
- 部分加载汇总显示未就绪，不把缺失余额算成确定的 0；保存后若额度已变化，展示后端冲突而非静默截断。
- 网络断开不得标为加载成功；重开或显式重试可重新请求，保留当前编辑不被晚到快照覆盖。

2. 请求经过处理、详情构造与落库后，快照存在；改名、删除、同名场景的身份筛选正确。
