# 后台设置、API Key 请求追踪与账号分配体验

## 目标

- 清除无实际配置意义、与运行行为不符的界面，同时保留有效设置。
- 管理员可以在请求详情中识别调用 Key，并通过下拉筛选追踪同一个 Key 的请求。
- 账号列表先出现，各账号额度查询结果逐条到达、逐条显示，不等待所有查询完成。
- 管理员可以从消费优先级列表快捷移除当前 Key 的账号分配，并在保存前撤销。

## 非目标

- 不改变 1M 窗口、900K 压缩线、真实 usage 返回或压缩协议。
- 不修改自动续写、首 Token 超时回退的后端行为和既有配置值。
- 不删除 Qoder 提供商账号，不重置消费用量，不改其他 Key 的分配。
- 不伪造或推测旧请求的 API Key 归属，不保证恢复历史上未记录的名称。
- 不扩大请求详情的保留期限，不承诺本轮上线或执行生产长上下文压缩验证。

## 已核实事实

- 设置页的主动守卫和压缩参数为禁用控件，但文字仍宣称提前拒绝以促使压缩；Qoder 执行器目前仅记录长度估算。
- 自动续写次数、首 Token 超时回退仍有实际后端消费者。
- `requestDetailsRepo.js` 的详情落库记录未专门保存 API Key ID 和名称，鉴权请求头会被清理；不能仅凭时间、模型或账号猜测请求归属。
- 详情接口提供服务端筛选与分页，但尚无 API Key 条件。
- `quota-options/route.js` 逐个查询账号额度，全部完成后返回 JSON；弹窗也等待完整 JSON。
- 现有取消勾选会移除表单中的账号、优先级和分配额度，保存后才生效。
- 现有策略中，空账号列表可能被当成不按账号限制；新移除入口必须避免引入意外放行。

## 用户流程与功能范围

### 1. 设置整理

- 删除原 Codex Compatibility 模块中的失效守卫、固定压缩比例、下限、上限控件及过时说明。
- 在当前设置页归入中文“请求重试与恢复”，保留“自动续写次数”和“首 Token 超时回退”。
- 继续支持读取、修改、保存这两项有效设置，保留旧值、允许范围和选项语义。
- 删除展示不等于删除后端固定策略或重试能力。

### 2. 请求详情的 API Key 名称

- 目标页面：`/dashboard/usage?tab=details`。
- 详情记录新增“API Key 名称”列，展示请求发生时的名称快照；后续改名或删除不改写历史名称。
- 新记录保留稳定 Key 身份，用于筛选，不以名称作为唯一身份。
- 筛选采用与现有“提供商”一致的下拉选择，不使用独立自由文本模糊搜索框。
- 下拉选择某个 Key 后，覆盖该 Key 改名前后的所有保留详情记录；表格各行仍显示各自调用时名称。
- 同名 Key 用非密钥的短 ID 区分，不使用密钥前缀区分身份。
- 支持全部 Key；与提供商、日期等现有条件组合，在服务端分页前筛选，总数与分页结果一致；更改条件从第一页开始。
- 已删除 Key 如有新格式历史记录，仍须能够按其保存的身份追踪，名称取历史快照，不因管理列表删除而失去筛选能力。
- 无法可靠关联的旧记录显示“未知（历史记录）”，不得误判为无 Key 调用，也不得挂到某个现有 Key 下。
- 对能够确定没有使用 Key 的新请求，与历史未知记录保持可区分的空值语义。

### 3. Qoder 账号增量加载

- 打开限制弹窗后先展示可获取的账号身份列表和已有选择、分配、优先级，再逐条接收并更新余额与额度信息。
- 查询未全部完成时，已经到达的结果必须可见；不是等到完整响应后再分批渲染。
- 每个账号独立区分加载中、成功、失败；缺失或失败的余额不是 0。
- 所选账号及必要分配数据就绪后即可保存；未选账号仍在加载或失败，不应阻塞保存。
- 所选账号额度未就绪或失败时，阻止不具备校验依据的额度保存，并明确对应账号状态。
- 后端保存时仍按最新必要数据校验，不因前端已有结果就跳过额度和其他 Key 分配校验。
- 已显示账号不因其他账号完成而跳动或覆盖用户正在编辑的选择、额度和优先级。
- 弹窗关闭或切换 Key 后，旧加载结果不得写入新的编辑会话。
- 汇总中依赖未就绪数据的值不能误显示为确定的 0；当前分配额度等已知值可正常展示。

### 4. 消费优先级快捷移除

- 在上下移动按钮旁增加 X 图标按钮，具有可访问名称和悬停说明。
- 点击 X 等价于取消该账号在当前 Key 中的选择：同步取消上方勾选、移除优先级和表单分配额度。
- 操作只修改当前表单，点击保存后生效；取消弹窗可以放弃修改。
- 不删除提供商账号、不修改其他 Key 分配、不触发用量重置。
- 启用限制时必须至少选择一个账号；允许在表单中暂时移空后重选，但禁止保存空列表。
- 上述空列表保护不能仅依赖前端按钮，保存入口也不得意外放行。
- 用户主动关闭限制时，沿用现有关闭行为；不顺带重解释数据库中既有空列表策略。

## 数据语义与业务规则

- 名称是请求发生时的历史快照；筛选键是稳定 Key 身份，两者职责分离。
- Qoder 账号身份与 API Key 身份不同，不可混用。
- 移除分配不等于删除历史请求或重置消费；其他仍保留账号的用量与配置不得被重置。
- 账号余额、分配额度、已用额度具有不同语义；增量加载不能把未知余额当作可分配额度。
- 所有选项与结果都遵循现有管理员权限和请求详情保留范围。

## 权限、安全与审计

- 复用现有后台鉴权，增量加载和筛选不得新增未授权数据入口。
- 返回 Key 名称、稳定 ID 所需信息，不新增密钥明文、鉴权头或凭证暴露。
- 同名消歧使用 ID，不使用密钥片段。
- 保存时继续校验额度，避免部分加载、过期余额或空选择造成超分配与越权使用。
- 本轮不另建审计系统；历史名称与稳定身份提供请求追踪依据。

## 异常、边界与验收条件

- 设置迁移前后两项有效值一致；旧压缩展示消失，压缩策略保持不变。
- 两个同名 Key 可分别筛选；同一个 Key 改名后可查到改名前后记录，行名称不被重写。
- 删除 Key 后新格式历史记录仍保留名称和身份；旧未知记录不错误补全或泄露密钥。
- 筛选与日期、提供商组合时，跨页记录、总数、清空行为正确。
- 一个账号很慢或失败时，其他已完成账号可见；未选失败账号不阻塞已就绪选择的保存。
- 所选账号失败时不能使用假 0 或缺失数据通过额度校验；后端额度冲突仍反馈失败。
- 增量结果到达不改变既有优先级，不覆盖正在输入的分配额度；切换 Key 不串数据。
- X 与取消勾选结果一致，取消不持久化，保存才生效；移除最后一个账号不能意外解除限制。
- 窄屏新增列和图标不重叠，控件可通过键盘操作。

## 风险

- 旧详情缺少可靠 Key 身份，无法承诺完整回填；用户已接受未知历史标识。
- 逐条查询结果有时间差，前端显示不能替代保存时校验。
- 现有空列表放行语义与新的移除交互存在冲突，必须保护新保存入口并兼顾旧配置兼容性。
- 真实流式到达可能受反向代理缓冲影响，后续验证需覆盖实际部署链路，不能只证明本地分批渲染。

## 已关闭问题

- 新请求使用调用时名称快照；无法可靠关联的旧记录不猜测归属。
- 使用与提供商一致的下拉，按 Key 身份筛选；同名用非密钥短 ID 区分。
- X 在保存后生效，可取消，不删除真实账号或重置用量。
- 先展示账号列表、逐条更新结果，所选账号及必要数据就绪即可保存。
