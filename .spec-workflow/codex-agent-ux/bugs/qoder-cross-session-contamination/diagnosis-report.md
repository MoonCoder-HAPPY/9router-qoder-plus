# Qoder 跨会话串线诊断报告

## 症状

同一 Qoder 账号下，多个客户端交互会话的上下文和流式回复可能互相出现在错误会话中；会话内容越积越乱。

## 诊断结论

已确认根因是 Qoder 请求构建器使用账号级身份生成上游 `session_id`：原实现只组合 `providerSpecificData.userId` 和模型名。同一账号、同一模型的所有客户端会话因此共享 Qoder 上游会话状态。

同时，`chatCore` 虽然已经从客户端请求头/请求体解析出会话标识用于日志标签，但没有将该标识传给执行器。`request_set_id` 和 `chat_record_id` 也未包含会话标识，在相同提示下会发生记录 ID 复用。

## 可复现循环

```text
npx vitest run tests/unit/qoder-session-isolation.test.js --reporter=dot
```

修复前结果：1 个测试失败；客户端 A/B 得到相同的 `session_id`（示例：`649d6cfd3a04e388`）。

修复后结果：3 个测试通过，覆盖不同会话隔离、同一会话稳定和原始请求头回退。

## 修复内容

- `chatCore` 将解析出的请求级客户端会话标识传递给首次执行和鉴权重试。
- Qoder 使用该标识生成作用域化的上游 `session_id`，不再按账号直接共享会话。
- `request_set_id` / `chat_record_id` 将上游会话标识纳入哈希，避免不同会话复用记录身份。
- 自动续跑沿用同一客户端会话标识；队列重试继续使用同一会话，同时保持请求级 ID 刷新逻辑。
- 无显式传入标识时，Qoder 仍从原始客户端请求头/请求体和连接信息回退解析，兼容直接调用执行器的路径。

- 隔离及相关 Qoder/Codex 测试：`8` 个测试文件，`95` 个测试通过。
- ESLint：通过。

- 全量 Vitest：受仓库既有路径别名、外部实时测试和环境依赖影响未全绿；未发现本次修改引入的 Qoder/Codex 相关失败。

## 清理与残余风险

- 未添加临时调试日志，未发现 `[DEBUG-*]` 调试标记。
- 未修改生产环境、数据库或部署配置。
- 如果某客户端完全不提供任何稳定会话标识，系统只能使用已有回退策略，无法从协议层可靠区分两个发送完全相同请求的独立会话；建议客户端发送 `x-session-id`、`x-client-request-id` 或请求体会话字段。
